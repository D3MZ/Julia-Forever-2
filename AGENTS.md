# Task completion

- Commit changes on a feature branch and open a PR to main. The merge-only GitHub workflow immediately integrates eligible, non-draft, conflict-free same-repository PRs; no regression, lint, differential, Aqua or JET checks gate PR merges.
- Use the `hold` or `no-automerge` label, or a draft PR, for work that must not merge automatically (including intentionally incomplete or insecure changes). Resolve Git conflicts explicitly, never with an unreviewed automatic conflict-resolution strategy.
- Do not treat a conflict-free Git merge as proof that the Julia package works. Keep the latest production behavior and security expectations intact. Cleanup and parity agents repair defects after integration.
- After integration, remove only task-related worktrees and branches; preserve unrelated work and uncommitted changes.

# Julia conventions

- Read and follow the [Julia style guide](https://docs.julialang.org/en/v1/manual/style-guide/) and [performance tips](https://docs.julialang.org/en/v1/manual/performance-tips/).
- Keep docstrings to a single line immediately above the function whenever possible.
- Prefer multiple dispatch and small functions over early short-circuit returns for unexpected behavior and over try/catch.
- Use `Base.@kwdef` when a struct's fields have sensible independent defaults; keep defaults beside the fields instead of repeating them in outer constructor arguments. Preserve established positional APIs with thin forwarding constructors, and retain inner constructors where validation or normalization is required.
- Review `if` statements for dispatch opportunities: use specialized methods for distinctions based on argument types (`Nothing`, `Bool`, collections, tasks, etc.), but keep conditionals for dynamic state, validation, ordering, and external protocol values. Test behavior across both paths.
- Do not write or edit documentation or README files; the user handles those. Update this instructions file when the user explicitly asks.
- The repository lint forbids `throw`, `rethrow`, `@assert`, and `try`/`catch` in Julia source.

# Scheduled quality ownership (no PR test gate)

- The hourly Julia Harness Refactoring automation owns repository-wide source lint, Aqua and JET. Its evidence is generated by `.github/workflows/refactoring-quality.yml` on a schedule or manual dispatch, not on PRs. Inspect the latest completed report and fix newly observed defects with focused PRs.
- To reproduce the scheduled checks manually: `julia --project=test -e 'using Pkg; Pkg.instantiate()'` followed by `julia --project=test test/runtests.jl lint aqua jet`. These are diagnostics, not merge blockers.
- Legacy regression, differential, and visual test suites, fixtures, and their separate oracle runner have been deleted. The `test/` directory retains only the quality runner, source-style lint, Aqua and JET. Do not recreate regression suites, test fixtures, differential harnesses or PR-time test workflows. Do not require quality checks before merging, and do not weaken an observable behavior or security contract to clear a warning.
- The scheduled VHS capture is in `.github/workflows/vhs-parity.yml` and `vhs/jf2.tape`. The scheduled Pi parity agent reviews screenshots and terminal evidence against pinned source behavior; a screenshot alone is not proof of program semantics, API compatibility, credential handling or correctness.
- Do not run real model or provider interactions or execute model-generated code without separate user authorization; the old live-model test runner has been deleted.

# Upstream-inspired parity work

- Compare current main with the pinned upstream Pi / DSH reference at known exact revisions. Keep DSH/Cordis/Pi integrations out of production: implement capabilities in native Julia with replaceable services, multiple dispatch and simple interfaces.
- Prefer observable behavioral evidence (scripted terminal traces, screenshots, exact protocol outputs, and explicit state transitions) over brittle positional assertions. Compare against pinned upstream source behavior and scheduled VHS evidence; do not recreate deprecated differential fixtures or require a red-green regression-test phase for ordinary PRs.
- A discrepancy must be reproduced and categorized before repair. Repair actual Julia behavior where its intended contract diverges. A proposed change to security expectations or approved visual baselines requires explicit review.
- Do not claim repository-wide upstream superset parity without complete independently grounded evidence for all material feature families. Record unverified and reference-only behavior truthfully; old capability matrices were removed with the test harness.
